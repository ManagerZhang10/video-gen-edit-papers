## 0. 这一轮解决的是什么问题

仓库 2026-09-01 从「视频生成」改名成「视频生成与编辑」，但**清单没跟着改**：

| | 改名前的 20 篇 | 扩充后的 50 篇 |
| --- | ---: | ---: |
| 只做生成 | 18 | 30 |
| 只做编辑 | **0** | **12** |
| 生成与编辑都做 | 2 | 8 |
| 编辑合计 | **2** | **20** |

原来那 2 篇（VACE、Kling-Omni）都是生成/编辑统一的工作，**专门做视频编辑的论文一篇都没有**。
README 的「已知没核到的」里已经把这条写成缺口。这一轮 30 个名额里 18 个给了编辑相关的工作。

时间跨度同时从 2023-11 → 2026-07 拉到 **2022-04 → 2026-08**。2022 那一头是必须补的：
视频编辑的起点比视频生成的产品化更早，Text2LIVE、Tune-A-Video 都是 2022 年的工作。

## 1. 候选池怎么来的

**上一轮踩的坑先说**：Semantic Scholar 的 `/paper/search` 端点在这台机器上无凭证直接 429，
46 组查询一条都没跑通。所以发现改成 **arXiv 查询网格 + HF Papers**，
Semantic Scholar 只用 `/paper/batch`（一次 400 个 ID，稳定）取引用量。

```
_work/exp50/arxiv_discover.py   arXiv API 32 条查询网格 × 最多 4 页 × 200 条        → ax_pool.json    5,390 篇
_work/exp50/discover_hf.py      HF 关键词检索 46 组 + 2024-06-01～2026-08-31 逐日   → hf_pool.json   16,620 篇
_work/exp50/resolve_seeds.py    71 条点名必查的经典，按标题走 arXiv ti: 检索定 ID   → seeds_resolved.json  64/71
_work/exp50/retry_seeds.py      7 条没解析到的换查询式重试                          → 补上 6 条
_work/exp50/fetch_cites.py      两池并集走 S2 batch 取引用/venue/DOI               → cites.json     19,968 篇
_work/exp50/rank.py             标题相关性筛选 + 算引用速率 + 出 6 张排序表          → r_*.tsv / e_*.tsv
```

`_work/` 被 `.gitignore` 挡住，重跑即可再生。全流程只用标准库 `urllib`。

**筛选后的规模**：19,968 篇里，标题命中「视频 + 生成/编辑」且不命中排除词（3D 高斯、
NeRF、医学、动作识别、视频问答、视频理解基准……）的 **4,924 篇**，其中标题带编辑类动词
（edit / inpaint / removal / stylization / customization / transfer / relight / swap / instruct……）
的 **1,041 篇**。30 个名额是从这 1,041 + 3,883 里挑的。

**网络可用性备注**：这台机器上 `huggingface.co` 无法解析（本地 DNS 返回 NXDOMAIN），
HF Papers API 走的是镜像 `hf-mirror.com`。已用已在库的 VACE 对齐过：镜像返回 58 upvote，
与 README 里 2026-08-31 记的 58 一致，判定镜像数据可用。

## 2. 两条轴，分开记

沿用原有口径：**影响力 = 已兑现的引用量 + 尚未兑现的业界关注度**，不合成单一分数。

| 轴 | 数据源 | 端点 | 核对日期 |
| --- | --- | --- | --- |
| 引用量 / 引用速率 | Semantic Scholar Graph API | `POST /paper/batch` | 2026-09-01 |
| 业界关注度（upvote） | Hugging Face Papers API | `GET /api/papers/<id>`（经 hf-mirror.com） | 2026-09-01 |

```
引用速率 = 引用总量 ÷ 首发至今月数        月数 = (2026-08-31 − 首发日) ÷ 30.44 天，下限 1.0
```

⚠️ **原有 20 条的数字是 2026-08-31 抓的，新增 30 条是 2026-09-01 抓的**，同一张表里混了两天的快照。
差一天的量级可以忽略（VACE 从 472 → 473），但要重算排序请整表重抓。

## 7. 这一轮的口径缺陷

| 缺陷 | 影响 |
| --- | --- |
| 发现依赖标题关键词 | 标题里不带 video / edit 类词的论文进不了池子。71 条点名种子是唯一的补丁，它是人工列的，必然有漏 |
| S2 `/paper/search` 不可用 | 上一轮图像侧用的「按相关度检索 + 按引用排序」这条路走不通，改成 arXiv 网格 + HF 池。arXiv 网格是按提交日期倒序取前 800 条，**极早期（2022 年及以前）的论文只能靠种子清单进池** |
| 引用速率假设线性累积 | 2022–2023 年的论文速率被低估，2025 年年中的被高估 |
| 2026-06 之后的论文两轴都失效 | 引用来不及攒，upvote 又受当天 daily papers 竞争影响。JoyAI-Video-Edit（11 天、1 引用）、Helios 这类只能靠技术判断，风险自担 |
| **编辑侧 2024 年是空的** | 新增的 18 篇编辑相关论文里，2023-11（InsV2V）之后直接跳到 2025-02（Señorita-2M），中间 15 个月没有一篇。2024 年编辑侧唯一够格的候选是 **AnyV2V**（2024-03，TMLR，150 引用 / 5.1 次每月 / 27 upvote），被同质的 training-free 那 6 席挤掉。**如果愿意放宽到 51 篇，它是首选补位** |
| 「某条线的根」是人判断的 | 第 3.3 节那 5 篇没有公式支撑，第 5 节把被换下的都列了出来供复核 |
| 编辑与生成的边界模糊 | ReCamMaster（重打相机）、Animate Anyone（姿态驱动）、Tune-A-Video（单视频调优）都可以两边归。`task` 是可多值字段就是为了不硬拆，但归几个值仍是人判断 |
