# 大白话深读《UniVideo》

## 1. 30 秒定位

这篇论文要解决的是：视频域里理解、生成、编辑仍被多个单任务模型割裂，缺少一个能读多模态指令并直接生成或编辑视频的统一系统。UniVideo 的办法是“双流”：一条冻结的多模态大语言模型负责指令理解与推理，另一条多模态扩散骨干负责视觉生成，两流分别送入语义特征和 VAE 精细视觉特征。代价是模型包含一个 7B 理解骨干和一个 13B 生成骨干，训练要分三阶段，推理同时跑语义前向与去噪过程；论文还承认在文本到图像细粒度指令跟随上不如部分统一基线。

## 2. 为什么这篇论文会出现

论文指出，统一多模态模型已经在图像域显示出“理解加生成”的能力，但视频仍被忽视（Introduction）。现有视频生成模型大多只做文本到视频单任务，依赖文本编码器处理指令，无法对多模态指令进行推理。视频编辑方法则通常使用任务专用模块或管线，例如 Ku 等、Jiang 等、Ye 等的工作，难以跨任务扩展。论文还提到两种失败路径：一类像 GPT-image-1 只用语义编码器，容易丢失细粒度视觉细节；另一类用可学习 query token 把输入压成固定 token，当指令包含视频时形成严重容量瓶颈。作者认为这导致多模态提示、上下文视频生成和自由形式视频编辑无法由单模型完成。因此 UniVideo 把 Qwen-Image、OmniGen2 这类图像双流思路搬到视频，目的是用一套参数统一多种生成和编辑任务，并通过多任务联合训练获得未见任务泛化。

## 3. 方法全景：先看数据流

先看整体数据流：

```
文本 / 图像 / 视频 / 标注草图
        │
        ├── 理解流 ──> MLLM (Qwen2.5VL-7B)
        │               └─ 最后层 hidden states
        │                        │
        │                        v
        │              可训练 MLP connector（4× 扩展）
        │                        │
        │                        v
        │              MMDiT 理解流（语义条件）
        │
        └── 生成流 ──> VAE encoder：参考图 / 源视频 / 条件图 -> latent
                        │
                        │ pad 到统一 shape，沿时间轴 concat
                        │ 加 3D positional embedding
                        v
                 MMDiT 生成流 + noisy video latent
                        │
                        v
                 denoised latent -> VAE decoder -> 输出视频 / 图像
```

理解流的核心是 MLLM。它接收文本、图像、视频输入，输出文本响应以及最后层隐藏状态。这些隐藏状态携带多模态输入的高层语义，被可训练 MLP 映射到 MMDiT 输入空间，作为语义条件进入生成骨干的“理解流”。论文没有给出 MLP 隐藏层维度，只说采用 4× expansion 对齐 Qwen2.5VL 与 HunyuanVideo 的特征维度。

生成流的核心是 VAE 和 MMDiT。图像、参考视频、源视频等视觉信号先由 VAE 编码成 latent；多张参考图或视频会被 pad 成统一形状，沿时间轴拼接，然后直接参与 self-attention。这样 MMDiT 不需要可学习 query token，也不会只靠语义特征，能直接看到重建级信号。论文强调这种视觉细节对视频编辑和身份保持很重要。

位置编码则采用 3D positional embedding：空间索引跨帧保持不变，只有时间维递增，让模型区分条件 latent 和待生成 noisy latent。论文在正文中写明，实践中这套位置编码比 Qwen2-VL 的 MRoPE 更有效，因为 MRoPE 每次引入新视觉输入就偏移所有轴（§2.2）。这部分只有文字说明，没有给出公式或详细张量形状。

MMDiT 两个分支最终合并完成去噪，输出 latent 再由 VAE decoder 还原成图像或视频。任务统一不依赖任务专用 bias embedding 或 context adapter，而是通过自然语言指令和统一条件格式完成。

## 4. 核心公式与直觉

本文正文没有给出编号公式，也没有披露损失函数、噪声调度或预测目标。PDF 抽取文本中未出现可解析的目标函数。因此只能从训练阶段和模块设计提炼三个起关键作用的“动作”，它们不是原文公式，但对应主要优化机制。

第一是对齐器的映射关系。原文只写“extract last-layer hidden states of the MLLM, aligned to the input space of MM-DiT via a trainable connector”。 可理解为 `semantic_cond = MLP(H_mllm_last)`。这里变量是 MLP 参数、MLLM 输出特征维度和 MMDiT 输入维度；优化动作是第一阶段只训练 MLP，让冻结的语义表征能驱动冻结的 MMDiT。工程对应就是 4× 扩展 MLP。

第二是去噪优化。从 Stage 1、Stage 2、Stage 3 的描述看，MMDiT 在文本、图像、视频条件下学习从噪声 latent 恢复到目标 latent，但因为正文没有损失公式，噪声预测方式是 ε、v 还是 x0，无法确认。这个目标牵引所有生成与编辑能力，尤其是多任务阶段：它迫使同一 MMDiT 在多类编辑指令和参考条件上共享去噪能力。

第三是条件的时空组织。原文没有显式公式，但用文字说明了视觉 latent 的拼接和位置编码原则：空间索引保持、仅时间维递增。这相当于对每一帧的空间坐标给相同位置特征，只为不同帧加时间增量，而不是把视觉条件当成全新序列重新编号。这个设计直接服务于“哪些 latent 是条件、哪些是待恢复目标”的区分，是 in-context 任务能工作的基础。

## 5. 训练与推理怎么跑

### 训练一轮 step

Stage 1 只练 connector。每轮采样 T2I、T2V 和图像重建样本；冻结 MLLM 和 MMDiT，只更新 MLP。文本或图像先经 MLLM 得到最后层隐藏态，MLP 映射后作为 MMDiT 语义条件；视觉侧经 VAE 得到 latent，MMDiT 做去噪或图像重建。论文提到图像重建任务里，只用 T2I 数据集中的图像送入 MLLM，MMDiT 用 MLLM 视觉特征重建图像。此阶段结束后模型能按文本或图像从 MLLM 生成图像和视频。

Stage 2 冻结 MLLM，训练 connector 和 MMDiT。样本是小规模高质量 T2I/T2V。一步训练中，文本理解仍来自 MLLM，但 MMDiT 参数开始被反向更新，使生成效果追平原始带文本编码器的 MMDiT 骨干。

Stage 3 冻结 MLLM，继续训练 connector 和 MMDiT。任务扩展为多 ID 到视频的 in-context generation、基于参考图的视频编辑（身份替换、增加、删除、风格迁移）、图像编辑、图像到视频，同时保留 T2I/T2V。每步根据任务组装不同视觉条件：参考图或源视频全部经 VAE 编码、pad、沿时间轴 concat，与 noisy latent 一起进 MMDiT。VAE 是否冻结，正文没有明确披露。数据规模、批次大小、训练时长、帧数、分辨率等也未在正文给出，论文指向 Appendix Table 7，但抽取文本未包含该表内容。

### 推理顺序

推理时先由用户输入文本指令和可选的参考图、源视频或标注草图。理解侧把全部多模态输入送进 MLLM，MLLM 产出需要返回的文本，同时其最后层隐藏态经 MLP 进入 MMDiT 语义条件。视觉侧把参考图、源视频等经 VAE 编码成 latent，pad 到统一形状，沿时间轴拼接并加 3D position embedding。对文本到视频任务是随机噪声 latent，对图像到视频或编辑任务则把源图像或源视频 latent 一并作为条件。随后 MMDiT 多步去噪，同时读语义流和 VAE 视觉流，最后 VAE decoder 输出视频或图像。“generation with thinking”场景中，MLLM 先把复杂视觉提示转成结构化计划和 dense prompt tokens，其 embedding 被 MMDiT 直接整合，论文强调这不是 agent 式调用多个下游生成器。

## 6. 实验和消融证明了什么

| 证据 | 任务/基准 | 关键数字 | 对照与说明 |
|---|---|---|---|
| 视频生成接近专用骨干 | VBench T2V | UniVideo 83.48，HunyuanVideo 83.24，Wan2.1 84.70 | 统一模型未明显落后专用骨干，但不是最高 |
| 文本到图像细粒度较弱 | GenEval | UniVideo 0.53，带 rewriter 0.69；OmniGen2 0.80，BAGEL 0.82 | 计数、位置等绑定任务明显弱于强统一基线 |
| 图像编辑能力较强 | ImgEdit-Bench | UniVideo overall 3.83，对比 OmniGen2 3.44，BAGEL 3.20 | 图像编辑没有因扩展到视频而崩溃 |
| 单参考 in-context 生成 | 人工 SC/PF/VQ | 0.88/0.93/0.95，Smooth 0.943，Aesth 5.740 | PF 略低于 Kling1.6 的 0.95，但总体领先或接近 |
| 多参考 in-context 生成 | 人工 SC/PF/VQ | 0.81/0.75/0.85 | 能处理多 ID，但 PF 相比单参考明显下降 |
| 关键消融：移除 MMDiT 视觉流 | 六任务平均 SC | UniVideo 0.78，w/o Visual for MMDiT 0.18 | 身份保持严重依赖 VAE 直接进 MMDiT 的路径 |

最关键的消融是“去掉 MMDiT 视觉流”。它让六个 in-context 任务的平均身份一致性从 0.78 掉到 0.18，说明仅仅把视觉输入送进 MLLM 不足以保持人物或参考对象身份。另一个正面证据是多任务学习消融：UniVideo 平均 PF 0.80、SC 0.78、VQ 0.85，明显高于同架构单任务基线 0.64、0.67、0.79（Table 6）。但必须注意：Table 1 的视觉理解分数是“reported using its MLLM backbone”，也就是直接报告 Qwen2.5VL-7B 的能力，并不一定代表统一训练后的实际 checkpoint。生成思考与零样本自由视频编辑也只有定性图例，没有系统指标。因此论文关于“理解能力不退化”和“未见任务泛化”的强主张，仍缺少统一点 checkpoint 的定量证据。

## 7. 与前作怎么选

| 方案 | 覆盖范围 | 关键差异 | 何时选 / 何时不选 |
|---|---|---|---|
| UniVideo | 图像+视频理解、生成、编辑 | 双流，MLLM 冻结，MMDiT 生成，mask-free in-context editing | 选：需要跨图像/视频多任务统一指令；不选：对 T2I 细粒度属性绑定要求极高 |
| OmniGen2 | 图像理解、生成、编辑 | 图像域统一模型，未覆盖视频 | 选：只要图像统一生成/编辑；不选：需要视频条件或 in-context video |
| HunyuanVideo | 文本到视频生成 | 单一 T2V 专用骨干，是 UniVideo 的 MMDiT 来源 | 选：只做 T2V 且要成熟专用流程；不选：需要编辑或图像任务 |
| UNIC | in-context 视频编辑 | 任务专家，需要 mask 指定编辑区域 | 选：可提供 mask 且只做特定编辑；不选：希望无 mask、跨任务 |

UniVideo 的核心卖点是跨任务和无 mask 编辑，但它不是所有基准上都最好。GenEval 上 OmniGen2 明显强得多；视频编辑的删除任务中，Task Table 5 显示 VideoPainter 在 PSNR 上为 22.987，UniVideo 只有 17.980。因此选型取决于是否愿意用较弱的文本到图像属性绑定和删除重建精度，换取一个模型覆盖视频理解、生成、编辑与上下文任务。

## 8. 工程判断与收束

数据层面，论文只给了任务范围，没有披露各阶段数据量、配比、去重、视频帧数、分辨率或清洗流程。正文说细节在 Appendix Table 7，但本抽取文本没有包含。算力与延迟也未披露，只能从结构估计：7B MLLM 前向加 13B MMDiT 多步去噪，再叠加 VAE 编码和解码；多参考视觉条件要沿时间轴 concat 并进 self-attention，帧数或参考图数量增加会显著放大序列长度。

实现难点主要在条件 latent 的统一形状。pad 到 uniform shape 会带来填充 token 的注意力浪费，统一尺寸也可能牺牲宽高比细节。三阶段多任务训练的配比需要仔细调，否则 T2I 绑定能力可能被视频任务拖累；GenEval 计数只有 0.23、带 rewriter 也只有 0.36，说明复合属性绑定仍是薄弱点。

最可能失败的环节是复杂多 ID 编辑和自由形式视频编辑。多参考 in-context generation 的 prompt following 从单参考 0.93 掉到 0.75，说明模型能记住身份，但不能稳定执行长指令。零样本自由视频编辑依赖图像编辑数据迁移，缺乏针对视频时序一致性、运动保持和跨帧语义编辑的定量验证，实际部署时容易时好时坏。

指标上限方面，理解分数用 backbone 报告，不能证明训练后的统一 checkpoint 真能保持该水平；生成思考也没有可量化的指令执行率。未来需要补一个同 checkpoint 的统一评测，覆盖理解、生成、编辑、多身份和自由形式编辑。

读完必须记住的 5 件事：
1. UniVideo 是双流系统：冻结的 MLLM 负责理解与指令推理，MMDiT 负责 VAE latent 去噪生成。
2. 视觉信息必须直接进 MMDiT；消融去掉 VAE 视觉流后，平均身份一致性从 0.78 跌到 0.18。
3. 训练分三阶段：只训 connector、再训 connector+MMDiT 做 T2I/T2V、最后多任务联合训练；MLLM 全程冻结。
4. 统一换来 VBench 接近 HunyuanVideo 与较强的图像编辑、无 mask in-context editing，但 GenEval 细粒度属性和多参考指令跟随仍然弱。
5. 零样本自由视频编辑与生成思考目前只有定性展示，表 1 理解分数用的是 MLLM backbone，而非统一训练后的实证结果。
