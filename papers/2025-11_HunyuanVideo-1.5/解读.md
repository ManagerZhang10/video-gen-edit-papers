# 大白话深读《HunyuanVideo 1.5》

## 1. 30 秒定位

HunyuanVideo 1.5 是腾讯混元团队在 2025 年 11 月 24 日公开的 8.3B 参数开源视频生成模型。它采用两阶段流水线：第一阶段用一个统一 Diffusion Transformer（DiT）同时支持文生视频（T2V）和图生视频（I2V），输出 480p 或 720p、5～10 秒的视频；第二阶段用专门的视频超分网络（Video Super-Resolution, VSR）提升到 1080p。论文重点落在三件事：SSTA 稀疏注意力把 10 秒 720p 视频合成的端到端速度相对 FlashAttention-3 提升 1.87×（Table 7）；双通道文本编码器 Qwen2.5-VL 加 Glyph-ByT5 改善双语理解和文字渲染；Muon 优化器加多阶段后训练提升运动连贯性。实验显示它在开源模型中相对 Wan2.2 取得 T2V GSB 胜率 17.12%、I2V 胜率 12.65%，但在 T2V 上与闭源 Veo3 对比胜率为 -10.32%（Table 5）。单卡 720p 121 帧推理峰值 13.6 GB，可跑在 RTX 4090 级别消费级 GPU 上。

## 2. 为什么这篇论文会出现

论文开篇把背景定在开源与闭源视频生成模型的差距：闭源的 Kling2.5、Veo3.1、Sora2 达到 SOTA，但不可访问；开源侧有 HunyuanVideo、StepVideo、Wan2.2 等竞争者，但存在明显效率或质量问题。论文特别点出 Wan2.2 的混合专家（MoE）架构用两个 14B 专家模型，总参数 27B、激活 14B，虽然视觉保真度不错，但“必须管理多个大参数集”，资源需求高；其 5B 压缩版虽然用高压缩 3D VAE 减小显存，但运动稳定性和专业级美学仍不足。因此论文认为存在一个“关键缺口”：缺少一个同时平衡高质量输出与高效推理的开源模型。

HunyuanVideo 1.5 的出发点就是造一个 8.3B 的紧凑模型，通过更激进的数据清洗、更高效的注意力、更紧凑的 VAE 以及多阶段训练，在不扩大到 20B+ 参数的前提下，逼近闭源模型质量。这个选择也解释了全文反复强调“轻量但强大”：参数少不只是工程癖好，而是为了让消费级 GPU 能跑完 720p→1080p 的完整流程。论文写明的目标不是全面超越 Veo3，而是在开源阵营建立新基准，同时把硬件门槛从多卡降到单卡。

## 3. 方法全景：先看数据流

HunyuanVideo 1.5 的核心数据流如下：

```
文本 prompt ──► 双通道文本编码器
                    ├─ Qwen2.5-VL (语义/场景/角色理解)
                    └─ Glyph-ByT5 (中英文字形精确渲染)
                    拼接后注入 DiT
                        
参考图像 (I2V) ──► 两条路径：
                    ├─ VAE Encoder → latent (通道维拼接，提供细节)
                    └─ SigLip → 语义特征 (序列维拼接，提供指令对齐)
                    + 可学习 type embedding 区分条件类型
                        
噪声 latent ───────────┐
                      ▼
              统一 DiT (8.3B)
              54 个 Dual-stream Block
              每 block: Self/Sparse-Attention + MLP
              3D RoPE 位置编码
                      │
                      ▼
               去噪 latent
                      │
                      ▼
               VAE Decoder
                      │
                      ▼
            低分辨率视频 (480p/720p, 5~10s)
                      │
                      ▼
          Video SR DiT (8.3B, 初始化自预训练 T2V 模型)
          输入: LR latent 通道拼接噪声
          + latnet upsample block 对齐空间
                      │
                      ▼
               VAE Decoder
                      │
                      ▼
                1080p 视频
```

**统一 DiT**：这是第一阶段的主干。它同时接受 T2I、T2V、I2V 三类任务。I2V 的参考图像走两条互补路径：VAE 编码后的 latent 沿通道维度与噪声 latent 拼接，目的是保留细节重建能力；SigLip 提取的语义 embedding 沿序列维度拼接，目的是增强语义对齐。可学习 type embedding 用来显式区分不同条件类型。论文 Table 1 给出 54 个 dual-stream block，模型维度 2048，FFN 维度 8192，注意力头 16，每头维度 128。

**VAE**：论文写的是 causal 3D transformer 架构，空间压缩 16×，时间压缩 4×，latent 通道数 32。这个压缩率属于较高压缩，直接减少 DiT 要处理的 token 数，是推理提速的重要来源。

**SSTA**：全称 Selective and Sliding Tile Attention。标准 self-attention 在视频序列上复杂度随 token 数平方增长，而视频存在时空冗余。SSTA 把 token 按 3D block 分组，先用块级 Q-K 相似度选出重要块，再与固定的局部滑动窗口 mask 结合，最后做 block-sparse attention。无参数，论文在蒸馏阶段引入以更好地保持质量。

**VSR**：第二阶段超分。论文明确写“遵循主模型架构——8.3B Video Diffusion Transformer”，在 latent 空间做超分。LR latent 与噪声沿通道拼接；训练一个单独的 latent upsample block 来空间对齐 LR/HR。VSR 模型初始化为预训练 T2V 视频模型，全部权重可训练。

## 4. 核心公式与直觉

论文没有展开扩散训练损失公式，最有信息量的公式在 SSTA 的 Algorithm 1 中。理解它足以抓住本文“计算效率”这条主线。

给定 query/key/value 张量 \(Q,K,V \in \mathbb{R}^{h \times F \times H \times W \times D}\)，先按 block size \(N = tile_t \times tile_h \times tile_w\) 划分成 \(B\) 个块。对每个块做 adaptive pooling，得到块级向量 \(\bar{Q}_b, \bar{K}_b\)。

第一步计算块间相似度：

\[
\text{Scores} = \bar{Q}_b \bar{K}_b^\top \in \mathbb{R}^{h \times B \times B}
\]

这里每个头 h 得到一个 \(B \times B\) 的块相似度矩阵，元素表示某个 query block 对某个 key block 的注意力价值。直觉类似：哪个 key block 对我的 query block 最重要。

第二步计算 key block 冗余度：

\[
\text{Scorer} = \frac{1}{N-1} \sum_{i=1}^{N} \sum_{j \neq i} [\bar{K}_b \bar{K}_b^\top]_{ij}
\]

这是 key block 内部任意两个子块相似度的平均：如果块内高度相似，说明这个 key block 信息重复度高，应该降低其被选择的优先级。

第三步合成块重要性分数：

\[
\text{Score}_i = \lambda \cdot \text{Scores} - \beta \cdot \text{Scorer}
\]

然后对 Score 做 Top-k 选择，得到选择性 mask \(M_{sel}\)。\(\lambda\) 控制“相关即重要”，\(\beta\) 控制“冗余要惩罚”。这一步是 SSTA 的动态全局选择：不同于固定局部窗口，它可以跨远距离选出关键块。

最后，\(M_{sel}\) 与预先定义的滑动 tile 注意力 mask \(M_{sta}\) 取交，得到 \(M_{combined}\)，再用 flex_block_attention 执行块稀疏注意力。这样既保留局部时序先验，又允许全局自适应选择，总体计算量远小于全注意力。

工程对应：论文用 ThunderKittens 框架实现加速版块稀疏注意力，并提到 SSTA 无参数，可在任意训练阶段插入。推理时对 241 帧 720p 视频，SSTA 比 FA3 快约 1.87×（Table 7 中 5.5070s / 2.9475s）。

## 5. 训练与推理怎么跑

### 一轮训练 step

论文没有给出单个 step 的精确伪代码，但结合数据、优化器和 flow matching 描述可以还原：

1. 从数据池采样图像或视频对，附带经过 captioning 模型生成的双语结构化文本。视频来自约 800M 高质量片段（过滤后），图像预训练 Stage I 有 5B、Stage II 有 1B。
2. 用因果 3D VAE 编码图像/视频为 latent（空间 16×、时间 4× 压缩）。
3. 按 flow matching 方式对视频 latent 加噪，构造网络输入。论文特别提到 flow matching 对 shift 超参数敏感，视频 token 长度变化时需要精心设计 shift scheduling。
4. 文本经 Qwen2.5-VL 与 Glyph-ByT5 双通道编码后注入 DiT；I2V 任务还会把参考图像 VAE latent 和 SigLip features 分别拼接。
5. DiT 前向预测，计算损失（论文未明示损失函数，但遵循 flow matching 范式），随后用 Muon 优化器更新参数。Muon 权重衰减设为 0.01，论文声称其达到更低训练 loss 只需 AdamW 一半训练步数。

后训练阶段（CT/SFT/RLHF）的 step 逻辑类似，只是数据规模缩至 1M 视频或 O(10K) prompt，目标从通用生成转向人类偏好。RLHF 中的 online RL 使用混合 ODE–SDE 求解器 MixGRPO，并对随机种子和 CFG 尺度做混合采样。

### 完整推理顺序

推理按以下顺序执行：

1. 输入文本 prompt（T2V）或参考帧 + 指令（I2V）。
2. 文本经 Qwen2.5-VL + Glyph-ByT5 编码；I2V 参考图像经 VAE 和 SigLip 分别编码。
3. 初始化随机噪声 latent（视频尺寸对应 480p 或 720p，帧数 121 或 241）。
4. 用 DiT 执行扩散采样。论文的推理速度测试基于 CFG 蒸馏模型，Table 8 采用 50 步报告总时间；Table 7 报告每步 wall-clock time，使用 8 张 H800 GPU 并开启 context parallelism。
5. VAE Decoder 把去噪 latent 解码为 480p/720p 视频。
6. 如果目标是 1080p，则把低分辨率视频经 VAE encoder 得到 LR latent，输入 VSR 模型按 flow matching 采样，再经 VAE Decoder 输出 1080p。
7. 单卡部署：论文写开启 pipeline offloading、group offloading 和 VAE tiling 时，720p 121 帧 T2V/I2V 全网端到端峰值显存为 13.6 GB，可跑在 RTX 4090 上（§6 末）。

## 6. 实验和消融证明了什么

### 关键证据表

| 证据 | 设置 / 指标 | 数值 | 对照 / 锚点 | 说明 |
|---|---|---|---|---|
| T2V 指令跟随弱于闭源 | Rating，instruction following | HY1.5 720p: 61.57 | Veo3: 73.77；Kling2.1: 50.03 | 论文模型并非全面超越闭源，指令跟随明显落后 Veo3（Table 3） |
| T2V 结构稳定性最高 | Rating，structural stability | HY1.5 720p: 79.75 | Wan2.2: 73.75；Veo3: 75.62 | 在评测的五维里这是 HY1.5 明显占优的维度（Table 3） |
| 相对 Wan2.2 的 T2V 优势 | GSB，HY Win Rate | 17.12% | Other better 17.78%，HY better 34.90% | 开源阵营中明确领先 Wan2.2（Table 5） |
| I2V 对 Wan2.2 的胜率 | GSB，HY Win Rate | 12.65% | HY better 45.60%，Other better 32.95% | I2V 同样强于 Wan2.2（Table 6） |
| SSTA 端到端加速 | 720p 241 帧，每步 wall-clock | 2.9475s (有 SSTA) vs 5.5070s (无 SSTA) | 相对 FlashAttention-3 约 1.87× | 最关键的效率消融：压缩比明显（Table 7） |
| 工程加速后仍有效 | 50 步总时间，720p 241 帧 | 58.39s (有 SSTA) vs 96.78s (无 SSTA) | SageAttention + torch.compile + cache | SSTA 与工程加速正交（Table 8） |
| 单卡显存 | 720p 121 帧 T2V/I2V 端到端 | 13.6 GB | 开启 offloading + VAE tiling | 支持 RTX 4090 级别单卡推理（§6） |

**最关键的消融**是 SSTA 的速度对比。因为论文的核心卖点是“轻量高效”，而 Table 7 直接给出 241 帧 720p 设置下每步 5.5070s 降到 2.9475s，与摘要中 1.87× 的声称完全对齐，并且 Table 8 显示在叠加上工程加速后仍能从 96.78s 降到 58.39s。这证明 SSTA 不是论文写作上的“软优化”，而是对长视频序列有可复现的 wall-clock 收益。

**尚未被证明的主张**主要有三处：第一，论文只说 SSTA “更有效地保持输出质量同时维持高计算效率”，但正文没有给出 SSTA 与 full attention 在视频质量、运动连贯性或多维 Rating 上的对等消融，因此“质量不降”目前是作者声明，不是实验支持。第二，RLHF 被描述为“一致改善所有指标，尤其是在运动现实主义方面”，但论文未在 §5 的 Table 中给出 RLHF 前后具体数值，难以量化收益。第三，VSR 的“显著增强视觉质量、运动稳定性和总体时序一致性”主要依赖 Figure 5 的定性可视化，没有提供 480p/720p vs 1080p 的定量指标或人类偏好对比。

## 7. 与前作怎么选

这里比较 HunyuanVideo 1.5、Wan2.2 和论文中提到的 HunyuanVideo 前代。后者的详细参数论文没有披露，只能从第 1 节的叙述推断其定位为 HunyuanVideo 1.5 的直接前身。

| 方案 | 参数规模 / 架构 | 效率特征 | 何时选 | 何时不选 |
|---|---|---|---|---|
| HunyuanVideo 1.5 | 8.3B 密集 DiT + 3D 因果 VAE + VSR | 空间 16×/时间 4× 压缩；SSTA 稀疏注意力；单卡 13.6GB | 需要开源可本地部署，同时兼顾 1080p 超分、双语指令和文字渲染 | 指令跟随要求接近 Veo3 的闭源级水平时不应选，Table 3 显示差距 |
| Wan2.2 | MoE，总 27B / 激活 14B；另有 5B 压缩版 | 需同时管理多个专家参数集，资源需求高；5B 版显存较小但运动稳定性不足 | 当显存极紧且只做短时长低分辨率任务时可考虑 5B 版 | 要高效推理同时保持运动质量时，论文数据显示 HY1.5 在 GSB 胜率上占优 |
| HunyuanVideo 前代 | 论文未披露参数 | 论文未详细说明 | 需要与既有前代工作流兼容、且对 1.5 新增 SSTA/VSR 无强依赖时 | 需要新数据管线、三任务联合训练、或中英文 glyph 文本渲染时选 1.5 |

选择的核心判断是：如果目标是开源可复现、单卡可跑、且输出 1080p 视频，HunyuanVideo 1.5 明显比 Wan2.2 的 MoE 路线更轻；但它不是无条件取代闭源。T2V 指令跟随只有 61.57 分，而 Veo3 是 73.77 分，复杂长指令场景下应该继续使用闭源接口。

## 8. 工程判断与收束

**数据侧**：预训练用了 5B 图像 + 1B 图像，视频原始数据 >10M 小时，过滤后约 800M 片段；CT 每任务 1M 视频，RLHF 中的 DPO 是 O(10K) prompt。这些规模本身不低，但相比 Wan2.2 等并未展开全部数据配方细节，复现时需自己重建去水印、转场检测和美学评分管线。最可能失败的数据环节是 captioning 的“丰富度-幻觉权衡”，论文用 OPA-DPO 优化，但评估该环节好坏的证据不在正文里。

**算力/延迟**：推理速度在 8 张 H800、context parallelism 下测得。无工程加速时，720p 241 帧每步 2.95s（SSTA）；加速后 50 步总 58.39s。单卡 121 帧 720p 显存 13.6GB。注意这些数字与硬件强绑定，消费级卡上延迟会更高、显存压力更紧。训练成本论文没有披露，只写 Muon 将收敛步数减半，不能推出总费用减半，因为单步开销可能不同。

**实现难点**：SSTA 的 flex_block_attention 依赖 ThunderKittens，工程上不是标准 Attention 接口；VSR 需要从 1K 到 4K 的 1M 视频片段，这类数据获取和清洗成本高；post-training 的 online RL 需要训练 VLM reward model 并在四维上评分，复现门槛远高于单纯 fine-tune。

**最可能失败的环节**：从实验结果看，T2V 指令跟随是 HunyuanVideo 1.5 最短板，Rating 低于 Veo3 约 12 分；而 GSB 对 Veo3 为 -10.32%。原因可能是双通道文本编码虽能改善字形和双语，但语义推理深度依旧不足。另一个风险是 SSTA 的块选择可能在高细节区域遗漏关键 token，但论文没有质量代价的量化消融来证明这一点。

**指标上限与未回答问题**：论文自称“开源新 SOTA”，在 GSB 上与 Wan2.2 对比确实成立，但绝对质量上限并未高于闭源。未回答的问题包括：SSTA 训练的蒸馏阶段如何影响最终质量？RLHF 前后 Rating 提升多少？VSR 在文本区域会不会放大伪影？I2V 的“instruction responsiveness”为何几乎与 HY1.5 720p 相同且低于 Kling2.1？这些问题决定该方案能否在真实创作流水线中替换 Wan2.2。

**读完必须记住的 5 件事**  
1. HunyuanVideo 1.5 是一个 8.3B 两阶段框架，先出 480p/720p，再 VSR 到 1080p，单卡可跑 13.6GB（§6）。  
2. SSTA 是无参数块稀疏注意力，同时用 Q-K 相似度选高价值块、用 K-K 冗余度惩罚重复块，720p 241 帧提速约 1.87×（Table 7）。  
3. 文本编码是 Qwen2.5-VL（语义）+ Glyph-ByT5（字形）双通道，I2V 参考图像走 VAE latent 拼接和 SigLip 特征拼接两条路。  
4. 训练分 T2I 先预热（5B/1B 图像），再 T2I:T2V:I2V = 1:6:3 混合预训练，最后 CT/SFT/RLHF；Muon 优化器以 AdamW 一半步数达到更低 loss（论文 §4.1）。  
5. 开源阵营中 HunyuanVideo 1.5 明确超过 Wan2.2（T2V GSB 胜率 17.12%），但 T2V 指令跟随 61.57 远低于 Veo3 73.77，不能用它代替复杂指令的闭源产品。
