# 大白话深读《Genie》

## 1. 30 秒定位

Genie 是一个生成式交互环境（generative interactive environments）模型，由 Google DeepMind 提出，发表于 ICML 2024。它只从无标签的互联网视频中训练，不需要人工标注的动作或文本，就能根据一张文本生成图、手绘草图或真实照片，生成一个可逐帧控制的虚拟世界。核心创新是学习一个离散的“潜在动作”（latent action）空间，让用户像按游戏手柄一样控制画面变化。模型总参数量约 11B，主要由三个组件构成：时空视频 tokenizer、自回归动力学模型、潜在动作模型。论文用 30,000 小时过滤后的 2D 平台游戏视频训练主模型，并展示了在机器人视频上的泛化能力，以及用学习到的潜在动作为未见过的强化学习环境训练策略的可能性。

## 2. 为什么这篇论文会出现

在此之前，生成模型在语言和图像上取得了很大进展，视频生成也开始受到关注，但视频模型大多只做“视频级生成”——给定文本或初始帧，生成一段连贯视频，用户无法在生成过程中逐帧干预。世界模型（world models）虽然能够做动作条件下的下一帧预测，但训练通常需要带真实动作标签的数据，例如机器人轨迹或游戏操作记录，而互联网上大规模视频几乎没有这类标签，人工标注成本很高。Genie 想填补这个缺口：直接从纯视频数据中，自动学出一套可控制帧变化的动作接口，从而让任何一段视频都能变成可交互环境。这样做的意义在于，如果能从海量公开视频中学习，就不再受限于有标签的模拟器或机器人数据，有可能为训练通用智能体（generalist agents）提供无限多样的环境。论文指出，现有世界模型如 GAIA-1、UniSim 需要文本和动作标签，而 Genie 只需要视频，且数据规模达到 20 万小时以上的互联网游戏视频。这是从“视频生成”走向“可玩的生成环境”的关键一步。

## 3. 方法全景：先看数据流

Genie 的训练分两阶段：先训练视频 tokenizer，再同时训练潜在动作模型和动力学模型。整体数据流如下：

```
训练阶段:
原始视频帧 x_{1:T} (T=16, 10FPS, 160x90)
        │
        ├──► 视频 tokenizer (VQ-VAE + ST-Transformer)
        │        输出离散 token z_{1:T}，每个帧被压缩为多个离散码
        │
        └──► 潜在动作模型 LAM (ST-Transformer)
                 输入: x_{1:t} 和 x_{t+1}
                 输出: 连续潜在动作 \tilde{a}_t → 量化成离散码 a_t (码本大小8)
                 训练时还有解码器从 x_{1:t} 和 \tilde{a}_t 重构 x_{t+1}
        │
        ▼
动力学模型 (decoder-only MaskGIT + ST-Transformer)
       输入: z_{1:T-1} (视频 token) + \tilde{a}_{1:T-1} (动作嵌入, stopgrad)
       预测: \hat{z}_{2:T} (下一帧 token)
       损失: 交叉熵(预测 token vs 真实 token)
       注意: 训练时对输入 z_{2:T-1} 随机 mask (mask rate 0.5~1)
```

推理时，用户先给一张初始帧 x_1，视频 tokenizer 编码成 z_1。用户选择一个离散潜在动作 a_1（0 到 7 的整数，码本大小 |A|=8），通过 VQ 码本索引得到动作嵌入。动力学模型接收 z_1 和 a_1，用 MaskGIT 迭代采样生成下一帧 token \hat{z}_2，再由 tokenizer 解码回像素。重复这个过程，就得到一条可交互的轨迹。注意，推理时整个 LAM 的解码器被丢弃，只保留 VQ 码本用于将用户的离散动作索引映射成嵌入向量。由于码本很小（8 个动作），用户可以像学习新游戏手柄按键一样快速理解每个动作的含义。

三个核心组件的输入输出和假设：

- **视频 tokenizer**：输入 T 帧原始视频，输出每帧的离散 token z_t。目的是把高维像素压缩到低维离散空间，降低动力学模型的生成难度。使用 VQ-VAE 目标，采用论文提出的 ST-ViViT 结构，用时空 transformer 同时做空间和时间建模，但空间注意力复杂度随帧数线性增长，比 C-ViViT 的二次增长更省显存。
- **潜在动作模型（LAM）**：输入相邻帧对（或历史帧和下一帧），输出连续潜在动作，再经 VQ 量化成离散码。它的训练信号来自“只用历史帧和动作就能重构下一帧”的重构损失，因此动作被迫编码帧间变化中有意义、可控的部分。码本大小限制为 8，保证人类可玩性。
- **动力学模型**：输入历史帧 token 和对应的动作嵌入，输出下一帧 token。采用 MaskGIT 风格的生成方式，在训练时随机 mask 部分输入 token，让模型学会从 masked token 恢复完整下一帧。使用 ST-Transformer 保证长序列生成效率。

## 4. 核心公式与直觉

论文没有给公式编号，但关键机制可以从以下三个公式理解。

**（1）VQ-VAE 量化目标**（潜在动作模型和视频 tokenizer 共享的思想）

LAM 用 VQ-VAE 目标训练。给定历史帧 x_{1:t} 和下一帧 x_{t+1}，编码器输出连续动作 \tilde{a}_t，经过码本量化得到离散动作 a_t。解码器再从 x_{1:t} 和 a_t 重构 \hat{x}_{t+1}。损失大致为：

```
L = ||x_{t+1} - \hat{x}_{t+1}||^2 + ||sg[\tilde{a}_t] - e_a||^2 + β||\tilde{a}_t - sg[e_a]||^2
```

其中 sg 是 stop-gradient，e_a 是码本中对应离散码的嵌入向量。第一项是重构损失，第二项让码本向量靠近编码器输出，第三项让编码器输出靠近码本向量。β 是权重。直觉：因为解码器只能看到历史帧和离散动作，动作必须携带“从历史到下一帧”的增量信息，否则重构失败。码本大小 8 意味着动作被压缩成非常低维的离散控制信号，类似于游戏手柄的按键。

**（2）动力学模型的交叉熵损失**

动力学模型在给定历史帧 token z_{1:t-1} 和动作嵌入 \tilde{a}_{1:t-1} 后，预测下一帧 token \hat{z}_t。损失是标准交叉熵：

```
L_dyn = - Σ_t Σ_i log p(\hat{z}_{t,i} | z_{1:t-1}, \tilde{a}_{1:t-1})
```

这里 i 是一帧内所有 token 的位置。训练时对输入 z_{2:T-1} 按 Bernoulli 分布随机 mask，mask rate 在 [0.5, 1] 之间均匀采样，这样模型既学会从完整历史预测，也学会从部分掩码的历史补全，推理时用 MaskGIT 迭代解码。

**（3）控制力指标 ΔPSNR**

论文定义 ΔPSNR 来量化潜在动作对生成的影响：

```
ΔtPSNR = PSNR(x_t, \hat{x}_t) - PSNR(x_t, \hat{x}'_t)
```

其中 x_t 是真实第 t 帧，\hat{x}_t 是用“从真实帧推断出的潜在动作”生成的帧，\hat{x}'_t 是用“随机采样的潜在动作”生成的帧。PSNR 越高表示与真实帧越接近。如果动作真的可控，那么用正确动作生成的帧应该比随机动作更接近真实帧，所以 ΔPSNR 越大越好。实验用 t=4 报告。

## 5. 训练与推理怎么跑

**训练一轮 step**

1. 从数据集采样一个 batch 的 16 帧视频片段（10FPS，160x90）。视频 tokenizer 已经预先训练好，将视频编码成离散 token z_{1:16}。
2. 潜在动作模型（LAM）接收这 16 帧原始像素，因果地推断每对相邻帧之间的潜在动作 \tilde{a}_{1:15}，并通过 VQ 码本量化成离散动作码 a_{1:15}。
3. 动力学模型接收 z_{1:15} 和动作嵌入 \tilde{a}_{1:15}（stop-gradient），目标是预测 z_{2:16}。训练时对输入 z_{2:15} 随机 mask，mask rate 从 [0.5, 1] 均匀采样。
4. 计算交叉熵损失，更新动力学模型参数。同时 LAM 也用自己的重构损失更新参数（注意 LAM 的编码器、码本和解码器都更新，但推理时只保留编码器和码本）。视频 tokenizer 在此阶段冻结。
5. 重复直到收敛。主模型使用 256 个 TPUv5p，batch size 512，训练 125k steps，总共处理 942B tokens。

**推理完整顺序**

1. 用户提供一张初始帧 x_1（可以是文本生成图、照片或手绘草图）。
2. 视频 tokenizer 的编码器将 x_1 编码为离散 token z_1。
3. 用户选择一个离散动作索引 a_1 ∈ {0,1,...,7}，通过 VQ 码本查出对应的嵌入向量 \tilde{a}_1。
4. 动力学模型接收 z_1 和 \tilde{a}_1，用 MaskGIT 迭代生成下一帧 token \hat{z}_2。每次生成一帧时执行 25 步 MaskGIT 采样，温度设为 2，随机采样。
5. 视频 tokenizer 的解码器将 \hat{z}_2 解码为像素 \hat{x}_2，显示给用户。
6. 将 \hat{z}_2 和新的动作索引 a_2 输入动力学模型，生成 \hat{z}_3，以此类推，自回归生成整个交互轨迹。
7. LAM 在整个推理中不参与，除了码本被用来映射动作索引。

论文指出推理速度约 1FPS，因此实时交互尚未实现。另外，动力学模型只有 16 帧的记忆窗口，长轨迹的一致性是限制。

## 6. 实验和消融证明了什么

| 证据 | 实验设置 | 结果与结论 | 证据锚点 |
|------|----------|------------|----------|
| 模型大小 scaling | 动力学模型从 40M 到 2.7B 参数，固定 tokenizer 和 LAM | 训练损失随 FLOPs 单调下降，说明架构可以随规模受益 | Figure 9 左/中 |
| 批量大小 scaling | 2.3B 模型，batch size 128/256/448 | 损失随 batch size 增大而下降，进一步支持规模化 | Figure 9 右 |
| 潜在动作模型输入消融 | 比较像素输入 vs token 输入 | 像素输入在平台游戏上 FVD 略差（40.1 vs 38.8），但控制力 ΔPSNR 更高（1.91 vs 1.33）；在机器人上 FVD 和控制力都更好（136.4 vs 257.8，2.07 vs 1.65） | Table 2 |
| Tokenizer 架构消融 | 比较 ViT、C-ViViT、ST-ViViT | ST-ViViT 在 FVD（81.4）和 ΔPSNR（1.66）上均最好，显存 0.9GB 居中；C-ViViT 显存最高但性能最差 | Table 3 |
| 机器人数据泛化 | 2.5B 模型训练在 Robotics 数据集上 | 达到 FVD 82.7，学习到机器人臂的上下左右等一致动作，以及物体形变 | §3.2, Figure 13, Figure 11 |
| 智能体训练 | 冻结 LAM 标注 CoinRun 专家视频，用 200 个真实动作样本映射后训练策略 | 达到与 oracle 行为克隆相同分数，远高于随机基线 | Figure 15 |

最关键的一个消融是 **潜在动作模型的输入选择**（Table 2）。它直接验证了论文的核心设计：如果 LAM 用 token 而不是原始像素，控制力会下降，说明 tokenizer 压缩会丢失对控制至关重要的运动细节。这一选择贯穿全文，影响了模型结构和最终性能。

尚未被证明的主张包括：潜在动作的语义一致性是否在所有域都成立（论文只在平台游戏和机器人数据上做了定性展示）；Genie 能否真正用于训练通用智能体（只在 CoinRun 上做了小规模实验）；以及长轨迹一致性（论文承认 16 帧记忆限制）。此外，论文没有放出模型权重或训练数据，第三方无法复现主模型，只能依赖附录 F 的小规模可复现示例。

## 7. 与前作怎么选

| 方案 | 训练数据要求 | 可控性 | 代表性工作 | 何时选 Genie |
|------|-------------|--------|------------|--------------|
| 世界模型 | 视频 + 真实动作标签 | 帧级 | GAIA-1, UniSim, IRIS | 没有动作标签，或动作标签覆盖不全 |
| 视频生成模型 | 视频 + 文本/标签 | 视频级 | Phenaki, TECO, MaskViT | 需要逐帧交互控制，而非被动观看 |
| 可玩视频生成（PVG） | 视频，但域特定静态数据 | 帧级 | Menapace et al. 2021/2022 | 需要从任意图像提示生成新环境，而非仅重放已知视频 |
| Genie | 纯视频，无动作或文本标签 | 帧级，8 个离散潜动作 | 本文 | 拥有大规模互联网视频、追求开放式生成环境 |

选择 Genie 的核心条件：训练数据只有视频，且希望用户或智能体能在生成过程中逐帧控制。如果已经有大量带动作标签的数据，经典世界模型可能更直接、控制更精确；如果只需要生成视频而不需要交互，视频生成模型更成熟。Genie 的 8 个离散动作是粗粒度控制，且推理约 1FPS，不适合需要精细操作或实时反馈的场景。

## 8. 工程判断与收束

**数据需求**：主模型使用 55M 个原始 16 秒片段，过滤后 6.8M 个片段（约 30k 小时）。这个规模对于 2D 平台游戏域足够了，但扩展到任意互联网视频可能需要更大数据清洗和多样性处理。论文未披露数据版权和过滤细节。

**算力/延迟**：训练使用 256 个 TPUv5p，125k steps，处理 942B tokens，对应 10.7B 参数模型。推理每帧 25 步 MaskGIT 采样，约 1FPS，远未达到实时交互（通常需要≥30FPS）。对于实际部署，需要大幅降低采样步数或使用蒸馏、缓存策略。

**实现难点**：ST-Transformer 的实现需要高效处理空间和时间注意力交替，且空间注意力随帧数线性增长的设计需要仔细的并行策略。VQ-VAE 码本训练容易出现码本坍缩或利用不充分，尤其是动作码本只有 8 个码字。动力学模型使用 MaskGIT 训练时，随机 mask rate 从 0.5 到 1，需要调节采样步数和温度以保证生成质量和多样性。

**最可能失败的环节**：潜在动作空间的一致性。虽然论文在平台游戏和机器人上展示了动作跨提示一致，但无法保证在 OOD 图像（如真实照片）上每个潜动作都有可解释、稳定的语义。如果动作含义漂移，用户交互体验会断裂。另外，16 帧记忆窗口导致长轨迹中背景或角色状态可能突变。

**指标上限**：FVD 和 ΔPSNR 都是离线评估，不能完全反映人类感知的交互质量。尤其是 ΔPSNR 只比较 t=4 的一帧，无法评估长轨迹的控制一致性。论文没有给出人类评估。因此，当前指标可能高估模型的真实可玩性。

**未回答问题**：如何将潜动作映射到具体语义动作（如“跳跃”或“向左走”）？论文通过人工试玩学习按键，但这需要用户自行探索。能否在更大规模、更多样化的视频上训练而不损失控制一致性？能否将潜动作迁移到真实机器人控制？论文只在仿真 RL 环境做了策略学习实验。另外，模型没有开源权重，社区无法直接验证。

**读完必须记住的 5 件事**

1. Genie 从纯视频中通过 VQ-VAE 学出 8 个离散潜在动作，无需任何动作标签就能实现帧级控制。  
2. 三个组件是视频 tokenizer（ST-ViViT，200M 参数）、潜在动作模型（LAM，300M 参数，像素输入）和动力学模型（MaskGIT + ST-Transformer，10.1B 参数）。  
3. 主模型在 30k 小时 2D 平台游戏视频上训练，总参数量约 10.7B（论文另称 11B），推理速度约 1FPS。  
4. 关键消融证明 LAM 必须用原始像素而不是 token 输入，否则控制力下降（ΔPSNR 从 1.91 掉到 1.33）。  
5. Genie 展示了将学到的潜动作用于训练策略（CoinRun 上 200 个样本即可匹配 oracle BC），但长轨迹一致性和实时性仍是限制。
