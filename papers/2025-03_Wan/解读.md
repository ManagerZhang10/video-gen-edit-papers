# 大白话深读《Wan》

## 1. 30 秒定位

Wan 是阿里团队于 2025 年 3 月 26 日发布的开源视频基础模型套件，采用主流的 Diffusion Transformer（DiT，扩散变换器）加 Flow Matching（流匹配）范式。论文同时开源 1.3B 与 14B 两个参数规模的文本生成视频模型，并覆盖图像转视频、视频编辑、个性化、相机控制、实时生成、音频生成等任务。核心贡献包括：一个 4×8×8 压缩比的三维因果 VAE（Wan-VAE）、共享自适应归一化层以提升同参数下网络深度、基于 umT5 的多语言文本编码、大规模数据清洗管线、自动化评测基准 Wan-Bench，以及支持中英文视觉文字生成的能力。14B 模型在 VBench 总分 86.22%，1.3B 模型宣称推理仅需 8.19GB 显存。论文定位为全面开源的视频生成基础模型，意图缩小开源与闭源模型差距。

## 2. 为什么这篇论文会出现

Sora 发布后，视频生成受到广泛关注，但开源模型与最新闭源商业模型之间仍存在三个主要差距。第一是**性能不足**：论文指出 HunyuanVideo、Mochi、CogVideoX 等开源模型虽逐步追赶，但在运动幅度、物理合理性、视觉文字生成等维度仍落后于闭源模型。第二是**能力单一**：多数开源基础模型只做通用文本转视频，难以满足创作所需的图像驱动、编辑、个性化等复合需求。第三是**效率不足**：大规模视频模型对显存和推理时间要求高，创作者难以在消费级硬件上使用。

这些问题共同限制了开源社区在视频生成方向的迭代。Wan 的出现直接回应这三点：用 14B 模型追求在多个内部/外部基准上对标甚至超过闭源方案；用统一基础模型扩展出八种以上下游任务；用 1.3B 模型将显存需求压缩到 8.19GB，允许在多数消费级 GPU 上运行。此外，论文强调开源代码和全部权重，以促进学术和工业复现。因此，Wan 不是单一模型，而是一个以“开放、全面、高效”为目标的工程与算法系统。

## 3. 方法全景：先看数据流

Wan 的核心是文本转视频（T2V）系统的三部分：Wan-VAE、视频 DiT 和 umT5 文本编码器。下面先画主训练/推理数据流，再拆组件。

```text
输入文本 prompt
      │
      ▼
umT5 文本编码器 ────────────► 文本嵌入序列 c_text (512 tokens)
                                    │
输入视频 V ∈ R^(1+T)×H×W×3        │
      │                              │
      ▼                              │
Wan-VAE 编码器（3D 因果卷积）        │
      │                              │
      ▼                              │
潜在特征 x ∈ R^(1+T/4)×H/8×W/8     │
      │                              │
      ▼                              │
3D 卷积 patchify（kernel (1,2,2)）   │
      │                              │
      ▼                              │
展平为 token 序列 (B, L, D)          │
      │                              │
      └──────────┬───────────────────┘
                 ▼
         N 个 DiT 块
   每个块内：自注意力（全时空）→ 交叉注意力（文本）→ FFN
   时间步 t 通过 MLP 生成 6 个调制参数，作用于归一化层
                 │
                 ▼
        输入噪声 x0 与 x1 线性插值得到 xt（训练时）
        模型预测速度 u(xt, c_text, t)
                 │
                 ▼
        损失 MSE(u, x1 - x0)（训练）
        推理时从纯噪声开始多步去噪，输出潜在
                 │
                 ▼
        Wan-VAE 解码器 ──► 视频像素
```

**Wan-VAE**：输入为 (1+T)×H×W×3 的视频，输出为 (1+T/4)×H/8×W/8×C 的潜在，其中 C=16。它采用三维因果卷积，保证时间因果性（未来帧不参与当前帧计算）；将所有 GroupNorm 换成 RMSNorm 以支持特征缓存推理；空间上采样层输入通道减半，减少约 33% 推理内存。VAE 总参数量 127M。训练分三阶段：先训 2D 图像 VAE，再膨胀为 3D 视频 VAE 做低分辨率预热，最后用 GAN 损失微调。目的是获得高压缩率、低失真且可处理任意长视频的潜空间。

**视频 DiT**：输入是 VAE 编码后的潜在 token 序列，形状 (B, L, D)，其中 L=(1+T/4)×H/16×W/16。patchify 使用 3D 卷积，核尺寸 (1,2,2)，因此在空间上又做 2 倍下采样。每个 DiT 块包含：全时空自注意力、对文本嵌入的交叉注意力、前馈网络，以及共享的时间步 MLP 生成 6 个调制参数（scale/shift 等）。文本嵌入由 umT5 生成，固定 512 token 长度。时间步 t 从 logit-normal 分布采样，经过一个共享 MLP 和 SiLU 后输出调制参数，每个块学习独立偏置。这种共享设计减少了约 25% 参数量，实验表明在相同参数量下增加网络深度收益更大。

**训练数据与目标**：预训练数据包括数十亿图像和视频，经过基础维度过滤（OCR、美学、NSFW、水印、模糊等）、视觉质量聚类打分、运动质量六分类筛选等四步清洗。视觉文字数据由合成纯白背景中英文字符图和真实 OCR 图像配对构成。后训练用高质量精选数据继续微调。训练目标为 Flow Matching 的 MSE 损失，详见下一节。

## 4. 核心公式与直觉

Wan 采用 Flow Matching / Rectified Flow 框架训练生成模型。训练时，给定真实视频或图像潜在 \(x_1\)，采样标准高斯噪声 \(x_0 \sim \mathcal{N}(0,I)\)，以及时间步 \(t \in [0,1]\)（从 logit-normal 分布采样）。中间潜在 \(x_t\) 定义为线性插值：

\[
x_t = t x_1 + (1-t) x_0
\]

对应的真实速度（velocity）为：

\[
v_t = \frac{dx_t}{dt} = x_1 - x_0
\]

模型 \(u(\cdot;\theta)\) 以 \(x_t\)、文本嵌入 \(c_{txt}\) 和时间步 \(t\) 为输入，预测速度 \(v_t\)。损失函数为：

\[
\mathcal{L} = \mathbb{E}_{x_0,x_1,c_{txt},t} \| u(x_t, c_{txt}, t; \theta) - v_t \|^2
\]

**直觉与工程对应**：Flow matching 不直接预测噪声，而是预测“从噪声指向真实样本的直线方向”。由于 \(x_t\) 是线性路径，训练目标简单且稳定，避免传统 DDPM 的复杂方差调度。推理时，从 \(x_0\sim\mathcal{N}(0,I)\) 出发，用 ODE 求解器积分速度预测 \(u\)，逐步得到最终潜在。对应工程上，每个训练 step 只需要一次 DiT 前向和一次 MSE 反向；推理约 50 步，每步调用 DiT 一次。长序列下注意力计算占主要成本（论文称当序列长 100 万 token 时注意力可占端到端训练时间 95%），因此后续的分布式、缓存和量化优化都围绕“减少注意力开销”展开。

## 5. 训练与推理怎么跑

**训练一个 step 的流程**：

1. 从数据集中采样一批视频或图像，视频经过 Wan-VAE 编码器得到潜在 \(x_1\)；图像也视为单帧视频。
2. 采样标准高斯噪声 \(x_0\) 和时间步 \(t\)，构造 \(x_t = t x_1 + (1-t) x_0\)。
3. 将文本 prompt 送入 umT5，得到 512 token 的文本嵌入 \(c_{txt}\)。
4. 将 \(x_t\) 经 patchify 成 token 序列，与文本嵌入和时间步一起输入 DiT。
5. DiT 输出预测速度 \(u(x_t, c_{txt}, t)\)，与真实速度 \(x_1 - x_0\) 计算 MSE 损失。
6. 反向传播更新 DiT 参数。Wan-VAE 与 umT5 在 DiT 训练阶段冻结。
7. 优化器为 AdamW，bf16 混合精度，初始学习率 1e-4，根据 FID 和 CLIP Score 平台期动态降低。

**预训练与后训练**：14B 模型先做 256px 低分辨率图像预训练，以解决直接高分辨率视频训练导致的吞吐低和梯度方差大问题。随后进入三阶段图像-视频联合训练：第一阶段 256px 图像 + 192px、16fps、5 秒视频；第二阶段升到 480px；第三阶段升到 720px。后训练阶段保持优化器与架构不变，在 480px/720px 高质量视频数据上继续训练。

**完整推理顺序**：

1. 用户输入简短 prompt，先由 Qwen2.5-Plus 进行提示改写，扩展细节、动作描述，并模仿训练 caption 的结构（风格后接内容摘要再细节）。目的是对齐训练 caption 分布。
2. 改写后的 prompt 输入 umT5，得到文本嵌入。
3. 初始化噪声潜在 \(x_0\sim\mathcal{N}(0,I)\)，设置时间步序列（约 50 步）。
4. 从 \(t=1\) 到 \(t=0\) 逐步积分：每一步将该步 \(x_t\)、文本嵌入、时间步输入 DiT，得到速度预测，按 ODE 求解器更新 \(x_t\)。分类器自由引导（CFG）会同时计算无条件预测，计算量翻倍。
5. 为加速，使用扩散缓存：对注意力输出每隔几步缓存复用，对无条件分支同样缓存并使用残差补偿。论文称在 14B T2V 上提升 1.62×。
6. 推理中 DiT 的 GEMM 操作使用 FP8 量化提升 1.13×；8-bit FlashAttention 进一步提升 1.27×。
7. 在多 GPU 场景使用 FSDP 模型切分和 2D 上下文并行（Ring Attention 外层、Ulysses 内层），可实现近线性加速比。
8. 最后将去噪后的潜在送入 Wan-VAE 解码器还原为视频像素。

## 6. 实验和消融证明了什么

以下是至少 4 条关键证据，均来自论文。

| 证据类型 | 任务/数据集 | 指标 | 对照与数值 | 锚点 |
|---|---|---|---|---|
| 综合基准 | Wan-Bench，1035 个 prompt | 加权分数 | Wan 14B: 0.724；Sora: 0.700；CN-TopA: 0.693；Hunyuan: 0.673 | Table 2 |
| 公开榜单 | VBench | 总分 / 语义 | Wan 14B: 86.22% / 84.44%；Sora: 84.28% / 79.35%；Hunyuan 开源版: 83.24% / 75.82% | Table 4 |
| 人类评估 | T2V 配对比较，超 20 人，4 个维度 | 胜率差 | Wan 14B 对 CN-TopA 在视觉质量胜出 30.6%、对 Runway 胜出 48.1% | Table 3 |
| VAE 效率 | 720×720、25 帧、200 视频 | PSNR vs 帧/秒 | Wan-VAE 参数量 127M，重建速度是 HunYuan Video 的 2.5×；同压缩 4×8×8 | Fig.7, §4.1.4 |
| I2V 人类评估 | 896 轮配对 | 总体排名胜率差 | Wan-I2V 对 CN-TopD 胜出 81.6% | Table 7 |

消融研究主要回答了“同参数量下把钱花在哪里”。最关键的是 **共享自适应归一化（adaLN）消融**：固定约 1.5B 参数，比较“一半共享一半不共享”与“全共享但增加 5 层网络深度”，结果显示后者训练损失更低；1.7B 的非共享 adaLN 反而比全共享 1.5B 差。结论是**把参数用于加深网络，比增加 adaLN 容量更有效**。第二个消融比较 umT5、Qwen2.5-7B 和 GLM-4-9B 作为文本编码器，umT5 训练损失最稳定，且比 Qwen-VL-7B 的 FID 更低（43.01 vs 42.91/43.72）。第三个消融比较 VAE 重建损失与扩散损失（VAE-D），显示重建损失 VAE 在 10k 步 FID 42.60 优于 VAE-D 的 44.21。

**尚未被充分证明的主张**：论文未给出训练总 GPU 卡数、精确 token 数量、能耗或碳排放。14B 模型单卡推理 30 分钟这一耗时仅出现在局限性章节，没有与其他模型细粒度延迟对比。实时生成的 8–20 FPS 主要报告速度，缺少大规模质量退化数据。与 Sora、Runway 等闭源模型的对比依赖其公开 API 版本，无法验证其内部模型版本是否更强。此外，1.3B 模型“仅需 8.19GB VRAM”未明确绑定批次大小、帧数或分辨率，量化后质量损失也仅在实时章节定量提及。

## 7. 与前作怎么选

这里比较三个最接近的开源视频 T2V 模型：HunyuanVideo、Mochi、CogVideoX1.5。

| 模型 | 核心架构 | VAE 压缩 | 文本编码器 | 开源程度 | 主要优势 | 何时选 Wan |
|---|---|---|---|---|---|---|
| Wan 14B | DiT + Flow Matching，共享 adaLN | 4×8×8，因果 VAE | umT5 | 代码+权重全开源 | 中英文字生成、多任务扩展、VBench 领先、1.3B 低显存 | 需要通用 T2V/I2V、中文内容、多任务工作流 |
| HunyuanVideo | DiT + Flow Matching，MM-DiT 拼接文本 | 4×8×8 | MLLM | 权重开源 | 结构相似，语义打分接近 Wan，但 VBench 总分落后约 3% | 对潜在结构有既有工具链，不需要中文字符生成 |
| Mochi | DiT，MM-DiT | 6×8×8 | T5 | 权重开源 | 较早发布，社区适配较多 | 需要更长时序压缩或复用 Mochi 生态 |
| CogVideoX1.5 | DiT + Flow Matching | 4×8×8 | T5 | 权重开源 | 图片到视频和视频续写能力成熟，参数较小 | 优先轻量化和已有强化微调 pipeline |

**不选 Wan 的场景**：如果任务极度关注超长视频（几分钟以上）或专业影视级大运动保真，论文自述大运动下细节保留仍是短板；若需要本地低延迟实时生成且不接受量化损失，Wan 1.3B 虽轻但实时管线依赖 LCM 蒸馏和 TensorRT，会引入质量折衷；若团队已对 HunyuanVideo 或 CogVideoX 做过深度微调，切换成本可能较高。

## 8. 工程判断与收束

数据方面，论文称使用数十亿图像和视频，总 token 量约 O(1) 万亿，但未给出精确统计。清洗管线包含约 50% 的基础过滤率，后续还有质量聚类、运动分级、视觉文字构建等步骤。这意味着数据加工成本可能极高，且 OCR、美学分类器、NSFW 模型等组件均需内部训练，复现难度大。

算力与延迟上，14B 模型在单张“head-end GPU”上推理约 30 分钟；多卡使用 FSDP 与 2D CP 几乎线性加速。1.3B 模型 8.19GB 显存，适合消费级 GPU，但未明确对应最高分辨率与帧数。训练时 DiT 占整体计算 85% 以上，序列长 1M 时注意力占训练时间 95%，因此训练集群需要大规模上下文并行和激活 offload。实现难点集中在：三维因果 VAE 的特征缓存正确性、长序列下 Transformer 注意力的显存与通信重叠、FP8/INT8 量化对视频质量的稳定性、以及多阶段数据配比的工程调度。

最可能失败的环节是**长序列训练中的注意力计算与显存溢出**，以及**量化后中文字符与细节的退化**。论文在实时章节提到 TensorRT 量化会引入 flickering 或时序不一致，这种误差在高速运动或文字渲染上可能被放大。此外，闭源对比的公平性受 API 版本影响，Wan-Bench 的分项分数波动也提示自动评测仍与人类感知有差距。指标上限方面，VBench 总分 86.22% 是当前公开可查的上限，但该分数不代表生成视频可商用；在 Wan-Bench 加权分数 0.724 说明即使最好模型，在多个维度上离满分仍有明显空间。

读完必须记住的 5 件事：
- Wan 采用 DiT + Flow Matching 框架，用 127M 参数的三维因果 VAE 实现 4×8×8 压缩，核心损失是预测潜在速度的 MSE。
- 共享 adaLN 的消融证明：在同参数规模下，增加 DiT 深度优于增加每块自适应归一化容量。
- 14B 模型在 VBench 达 86.22%，1.3B 模型宣称 8.19GB 显存，但论文未披露精确训练算力与总 token 数。
- 推理加速组合包括 FP8 GEMM、8-bit FlashAttention、注意力/CFG 缓存和多卡 2D 上下文并行，但量化会引入可见伪影。
- 论文覆盖 T2V、I2V、VACE 编辑、个性化、相机控制、实时流式生成和 V2A 音频，但大运动细节保真与单卡 30 分钟延迟仍是明确局限。
