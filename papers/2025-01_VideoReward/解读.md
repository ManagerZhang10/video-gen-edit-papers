# 大白话深读《VideoReward》

## 1. 30 秒定位

这篇论文解决视频生成模型“运动不顺滑、文本-视频不对齐、不符合人类偏好”的问题。办法是构建一个 182k 人工标注三元组的大规模偏好数据集，训练多维度视频奖励模型 VideoReward（视觉质量 VQ、运动质量 MQ、文本对齐 TA 三维度），并在流匹配（rectified flow）框架下提出三种对齐算法：训练时 Flow-DPO、Flow-RWR，推理时 Flow-NRG。主要代价是：奖励模型用 Qwen2-VL-2B 骨干，对齐方法基于 LoRA 微调，Flow-NRG 还需要额外训练一个潜在空间奖励模型；训练中需要大算力跑 12 个视频生成模型和人工标注，但论文未披露具体卡数与耗时。核心发现是：Flow-DPO 采用恒定 KL 系数 β（而非时间依赖 βt=β(1-t)^2）才能避免奖励黑客（reward hacking）并稳定提升三维度。

## 2. 为什么这篇论文会出现

视频生成模型在 rectified flow 技术下已能产出逼真细节和连贯运动，但仍有运动不稳定、文本-视频错位、与人类偏好不一致的问题。语言模型和图像生成中，基于人类反馈的强化学习（RLHF）已被证明有效，但将 RLHF 应用到视频生成仍处早期，主要障碍是两个。

第一，可靠奖励信号缺失。现有偏好数据集如 VideoScore、LiFT 等收集的样本来自早期 T2V 模型，视频短、分辨率低、满是闪烁伪影。这些旧数据训练出来的奖励模型可能在当前高质量视频上无效：它会忽略精细空间细节和长程动态，同时过度惩罚现在模型已能抑制的故障，导致监督噪声大、偏差强，易被 RLHF 利用产生奖励黑客。

第二，现代视频生成模型的内部机制变了。主流新模型采用 rectified flow（flow matching）预测速度场而非噪声场。已有工作如 Diffusion-DPO 试图将 DPO 从扩散模型迁移到 video，但直接扩展时，其时间依赖的 KL 项使策略在高噪声层级过拟合目标，导致质量下降甚至比未对齐基线更差。因此需要一个针对 flow 范式、能同时覆盖奖励建模和对齐算法的系统研究。这正是本文工作的出发点：构建现代偏好数据集、系统设计奖励模型、推导 flow 版的 DPO/RWR 与推理时引导。

## 3. 方法全景：先看数据流

整体流程分三段：数据收集 → 奖励模型训练 → 视频对齐。ASCII 数据流如下：

```
[16k prompts] --12个T2V模型渲染--> [108k videos] --配对--> [182k triplets]
                                                        ↓  人工标注 VQ/MQ/TA
                                                 偏好三元组 + Likert分
                                                        ↓
                          训练 VideoReward (Qwen2-VL-2B + BTT + token定位)
                                                        ↓
                       三维奖励分数 r_vq, r_mq, r_ta
                        |                     |
           训练时: 生成偏好对D      推理时: 潜在奖励模型rθ(·,t)
                        |                     |
            Flow-DPO / Flow-RWR        Flow-NRG: 速度场偏移
                        |                     |
                   更新LoRA参数        控制采样生成个性化视频
```

**数据集构建组件**：输入是 16k 高质量 prompts，来自互联网收集并归为 8 个元类别（动物、建筑、食物、人物、植物、场景、车辆、物体），用 GPT-4o 扩展，再经内部 prompt rewriter 去掉重复、无关或不安全条目。12 个不同能力的 T2V 模型（包括 Gen2、Pika、Luma、Gen3、Kling 1.0/1.5 等）对每个 prompt 生成视频，共 108k 个视频。视频再配对成 182k 三元组，每个三元组是一个 prompt 和两个不同模型生成的视频。专业标注员对每个三元组在 VQ、MQ、TA 三个维度上给出偏好标签（A wins/Ties/B wins），并对单个视频打 1–5 的 Likert 分。13k 三元组被留作验证集，其 prompt 不出现在训练中。这一组件输出的是带多维度偏好标签的三元组集合。

**VideoReward 组件**：输入是一个视频和一个 prompt，骨干网络 Qwen2-VL-2B 编码后，通过 token 定位策略输出三个分数。具体是：在视频后、prompt 前插入两个上下文无关 token [VQ] 和 [MQ]，它们只 attend 视觉内容；在完整 prompt 后插入上下文相关 token [TA]，可同时 attend 视频和文本。最终层 embedding 经共享线性层映射为三个维度的奖励分数。输出是三维分数向量（r_vq, r_mq, r_ta），后续可线性聚合为总分。该组件的设计假设是：消除上下文泄漏能稳定视觉和运动的评分，避免同一视频在不同 prompt 下 VQ 分数变化。

**对齐阶段组件**：Flow-DPO 输入偏好三元组 (y, xw_0, xl_0)，用固定 β 的损失（公式 6）更新 LoRA 参数；Flow-RWR 输入单个视频及其奖励分数，用奖励加权速度回归更新参数；Flow-NRG 是一个推理时组件，输入当前噪声潜在 xt 和 prompt y，从轻量时间条件奖励模型 rθ(·,t) 计算奖励梯度，按公式（11）偏移速度场，输出新的采样方向。三者共享同一个奖励信号来源——VideoReward 或潜在奖励模型，但前两者改变模型参数，第三个不改变模型参数。

## 4. 核心公式与直觉

本贡献关键在奖励模型的 BTT 损失和 Flow-DPO 损失，以及 Flow-NRG 的速度场偏移。这里保留其中最关键的两个。

**公式（1）Bradley-Terry-with-Ties (BTT) 偏好分布**：定义三元组概率 Pθ(c|y, xA_0, xB_0)，c∈{Tie, A wins, B wins}。对于 A 赢的情况 Pθ = exp(rA)/(exp(rB)+θ exp(rA))，B 赢类似，Tie 情况分母变为 (exp(rA)+θ exp(rB))(θ exp(rA)+exp(rB))，分子为 (θ²−1)exp(rA)exp(rB)。θ>1 是 tie 倾向控制器，论文设 θ=5.0。训练目标是负对数似然（公式 2）。直觉：普通 BT 模型被迫对 tie 对也产生有偏的分数差 Δr，会导致奖励模型把质量相近的视频当成明显偏好；BTT 用一个有限边界把 tie 对的 Δr 压缩到零附近，同时保留明确胜负的大 margin，为下游 RLHF 提供更干净、更不容易被利用的奖励信号。工程上，BTT 只是损失函数从二分类扩展为三分类，模型结构不变。

**公式（6）Flow-DPO 损失**：L_FD(θ) = −E[ log σ( −(βt/2)·( ||vw−vθ(xw_t,t)||² −||vw−vref(xw_t,t)||² −(||vl−vθ(xl_t,t)||² −||vl−vref(xl_t,t)||²) ) ) ]。其中 vw、vl 是偏好/非偏好样本的真实速度，vθ 是当前模型，vref 是参考模型，xw_t 是偏好视频在时间 t 的噪声版本。直觉：这本质上是一个对比损失。σ 内是偏好视频预测误差与参考误差之差减去非偏好视频的对应量，取负对数后，模型被引导把偏好视频的速度预测误差降到低于非偏好视频的误差；σ 外面系数 βt 控制偏离参考的力度。关键发现是 βt 的形式：从扩散 DPO 直接映射会得到 βt = β(1−t)²（β 是 KL 正则系数，t 是 flow 时间步，t=0 对应干净视频，t=1 对应纯噪声）。该时间依赖使惩罚在 t 接近 1 时趋近于 0，迫使模型在高噪声层级过度拟合奖励目标，最终导致奖励黑客与视觉伪影。论文发现改用恒定 β 显著改善三维度，且避免了 VQ/MQ 高但 TA 崩塌的现象。

## 5. 训练与推理怎么跑

**奖励模型训练一个 step**：采样一个 batch 的三元组 (y, xA_0, xB_0, 标签 c)。视频和 prompt 送入 Qwen2-VL-2B，提取 [VQ][MQ][TA] 三个特殊 token 的最后一层 embedding，经共享线性层输出 r_vq、r_mq、r_ta。用公式（2）BTT 负对数似然作为损失。反向传播更新骨干网络和线性头的参数（论文未明确是否部分冻结骨干，但表示使用 2B 骨干）。视频采样设置：2 fps，约 448×448 分辨率，保持原始纵横比。超参数见 Appendix I，正文未复述具体学习率、batch size、epoch。

**Flow-DPO 一个训练 step**：从偏好数据集取 batch (y, xw_0, xl_0)。对每个样本采样时间步 t（flow 范式 t∈[0,1]），从标准高斯采样噪声 x1，构造 xw_t=(1−t)xw_0 + t·x1，xl_t 同理。当前模型 vθ 在 prompt y 条件下预测 vθ(xw_t,t) 和 vθ(xl_t,t)，参考模型 vref 在同样输入上做前向（不更新梯度）。计算公式（6）损失，其中 β 用固定值。更新 LoRA 参数，冻结原始 Transformer 全部参数和参考模型参数。SFT 只用选中视频做速度场回归，Flow-RWR 则用公式（9）的 exp(r(x0,y)) 加权速度回归，同样只更新 LoRA。

**推理顺序**：Flow-DPO/Flow-RWR/SFT 训练出的模型按标准 flow 采样：从纯噪声 x1~N(0,I) 出发，用学习到的速度场 vθ(xt,t) 数值积分（论文未披露采样器细节）从 t=1 到 0 生成 x0，再 VAE 解码成视频。Flow-NRG 是独立的推理时算法，流程是：对每个采样时间步 t（t≠1），正常计算速度 vt(xt|y)，同时用潜在空间奖励模型 rθ(xt,t) 计算对 xt 的梯度 ∇r(xt,y)，按公式（11）偏移速度场：ṽt = vt − w·(t/(1−t))·∇r(xt,y)。这里 w 是用户可调的引导强度，论文实验用 w=100。奖励梯度计算在 VAE 潜在空间进行，避免了对像素空间全解码器的反向传播。用户可以赋不同权重给 VQ/MQ/TA，如权重 0:0:1 即只最大化 TA。该过程不修改生成模型参数。

## 6. 实验和消融证明了什么

关键证据汇总如下表：

| 实验 | 数据集/指标 | 对比基线 | 结果 | 证据锚点 |
|---|---|---|---|---|
| 奖励模型现代泛化 | VideoGen-RewardBench, 总体 w/ties accuracy | VideoScore, LiFT, VisionReward | Ours 61.26 显著高于 VisionReward 56.77、VideoScore 41.80、LiFT 39.08 | Table 2 |
| 多维多目标对齐 | VideoGen-Eval, VQ/MQ/TA win rate | Pretrained, SFT, Flow-RWR, 时间依赖β的Flow-DPO | Flow-DPO(常数β)胜率 90.95/81.01/68.26，且 TA 未崩塌 | Table 3 |
| 单维 TA 对齐 | TA-Hard, TA win rate | Pretrained, SFT, Flow-RWR, 时间依赖β的Flow-DPO | Flow-DPO(常数β) 84.51，唯一大幅优于所有基线 | Table 4 |
| β 系数消融 | 多数据集 accuracy | βt=β(1−t)² vs 常数 β | 常数 β 在多个 β 值下均一致优于时间依赖版 | Figure 6 |
| Flow-NRG 权重定制 | VideoGen-Eval, 三维度得分 | 不同 VQ:MQ:TA 权重组合 | 权重 0:0:1 使 TA 达 70.42 但 VQ 仅 60.56；权重 0.5:0.5:0 使 VQ 86.43、MQ 93.23、TA 26.65 | Table 5 |

最关键消融是 β 系数恒定性。该消融解释了 Flow-DPO 的直接迁移为何失败：时间依赖 βt 把训练信号几乎全部压在高噪声层级，使模型学会在降噪后期"刷"奖励，而非真正提升语义对齐。Table 3 显示时间依赖版 TA 胜率只有 51.02（接近随机 50），而 VQ/MQ 却虚高到 87.78/82.36，这是典型的奖励黑客信号。改为常数 β 后 TA 恢复到 75.43，VQ 仍达 93.42。

尚未被证明的主张：第一，Flow-DPO 长时间训练会让质量恶化，作者仅在 Limitations 中如实说明，并未给出防止策略的实验；第二，奖励模型自身仍可能被黑客攻击，即生成质量下降时分数仍高，论文承认这一风险并建议未来加不确定性估计；第三，所有实验结果来自内部研究模型，未在外部开放模型上复现，泛化到其他 flow 架构仍未知；第四，Flow-NRG 的延迟没被测量，只说避免 VAE 反向传播可提高效率，但没报每步增量延迟。

## 7. 与前作怎么选

奖励模型与对齐方法两个层面的选择表如下：

| 方案 | 核心机制 | 现代视频泛化 | 主要限制 | 何时选 |
|---|---|---|---|---|
| VideoScore | CLIP型回归，点式 | 差，旧数据训练 | 现代视频上 VQ/MQ 准确性低 | 只评估旧式短片 |
| VisionReward | VLM 回归，多维 | 中，TA 尚可，VQ/MQ 弱 | 被现代高质量视频"蒙蔽" | 资源受限需简单回归 |
| VideoReward (Ours) | BTT + token定位，VLM | 优，三维度均最高 | 仍需大量标注数据 | 需要现代视频高保真奖励时 |

对齐方法比较：

| 方法 | 训练代价 | 多维度提升 | 训练稳定性 | 定制化 |
|---|---|---|---|---|
| SFT | LoRA，只用选中视频 | TA 提升有限 | 稳定 | 不支持 |
| Flow-RWR | LoRA，奖励加权回归 | TA 提升较弱 | 较稳定但上限低 | 不支持 |
| Flow-DPO(常数β) | LoRA，成对偏好 | 三维度均好 | 较好 | 不支持 |
| Flow-NRG | 不需训练生成模型，但需潜在奖励模型 | 可实时调权重 | 推理时控制 | 支持任意 VQ:MQ:TA 权重 |

选择指南：若只求简单，可用 Flow-RWR 但预期增益低于 Flow-DPO；若要跨维度偏好，Flow-DPO(常数β) 是训练时首选；若用户需要个性化权重且不想重训，Flow-NRG 唯一支持推理时定制。不要选时间依赖 β 的扩散 DPO 直接迁移，论文实验证明在 TA 上会崩。

## 8. 工程判断与收束

**数据层面**：论文覆盖了 12 个模型、16k prompts、182k 三元组，规模与多样性在视频偏好领域较大。但全部生成和标注由快手内部流水线完成，外部复现需重建类似标注协议和专业标注员，成本未披露。验证集 13k 三元组的 prompt 与训练不重叠是好的控制，但只在内部管线上验证。

**算力与延迟**：奖励模型用 Qwen2-VL-2B，训练成本低；视频对齐用 LoRA，计算可控。但 Flow-NRG 在推理的每个时间步都要对潜在计算奖励梯度，增加延迟，论文未给出具体延迟数字或批量吞吐。训练一个额外时间条件潜在奖励模型引入数据和算力开销，且需要复用预训练骨干前几层，细节在 Appendix C/E 中，正文未展开。

**实现难点**：token 定位的正确性依赖输入序列布局（video tokens → [VQ][MQ] → prompt tokens → [TA]），若 Qwen2-VL 的 tokenizer 或位置编码不同，需重新设计。BTT 的 θ 选择是超参数，论文设 θ=5.0 但没给出敏感度分析。Flow-DPO 固定 β 虽稳定，但在不同数据集或模型规模下是否仍优于时间依赖版，尚未验证。

**最可能失败环节**：奖励模型的奖励黑客风险是最大隐患。即便 token 定位和 BTT 缓解了部分问题，Limitations 明确承认生成质量下降时奖励分可能不降，这意味着下游 Flow-DPO 或 Flow-NRG 仍可能被优化到一个"分数高但人看烂"的模型。另外，Flow-NRG 的公式（11）在 t→0 时 t/(1−t) 趋向 0，引导力消失，极低噪声层级可能效率很差。

**指标上限**：奖励模型在 VideoGen-RewardBench 上最高 w/ties accuracy 为 61.26，带 ties 的准确率仍有近 40% 不确定，说明现代视频偏好评估十分困难。对齐实验用 VideoReward 作为自动评估器评测由 VideoReward 标注的数据，存在自评循环偏差，虽然有人类研究兜底（Figure 5），但只覆盖 VideoGen-Eval 一个数据源。TA-Hard 上 Flow-DPO 达到 84.51 的 TA win rate，但绝对 VBench 分数提升有限，VQ/MQ 的"胜率"虚高需警惕。

**未回答问题**：Flow-RWR 多维度对齐中 TA 提升不明显的原因未分析；PPO 未实现；多样性（diversity）没有直接用指标评估；仅在文本到视频任务上验证，图像到视频是否适用未验证。

读完必须记住的 5 件事：
- 这项工作的核心是：用 182k 现代视频偏好数据训练出 VideoReward 三维度奖励模型，然后针对 rectified flow 提出三种对齐算法。
- 奖励模型的关键设计是 BTT（处理 tie）和 token 定位（消除上下文泄漏）；BTT 中 θ=5.0，用 Qwen2-VL-2B 做骨干。
- Flow-DPO 中直接迁移扩散 DPO 得到的 βt=β(1−t)² 会导致高噪声层级过拟合和奖励黑客，必须改用常数 β。
- Flow-NRG 在推理时对速度场加 w·(t/(1−t))·∇r(xt,y) 偏移，用户可自定义 VQ/MQ/TA 权重，论文实验取 w=100。
- 实验证明 Flow-DPO(常数β) 在三维度胜率上稳定超过 SFT、Flow-RWR 和时间依赖版，但奖励模型仍有被黑客的风险，且全部结论仅在一个内部 T2V 模型上得到验证。
